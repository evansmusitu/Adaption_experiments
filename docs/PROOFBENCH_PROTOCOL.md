# MUSITU PROOFBENCH: experimental protocol

**Version:** 2026-11-20. **State:** pre-registration draft; research results have not been collected.

## Hypothesis

Independently verified, counterfactual examples will improve financial numeric correctness, paired answer sensitivity and appropriate requests for missing information, relative to a matched data expansion without verification.

## Preregister experiments before seeing outcome data

We need **two different kinds of evidence**, never merged into one score.

1. **Adaption-native dataset quality:** retain original imported dataset ID; run a properly cost-quoted Adaption adaptation; retain adapted dataset/run ID, exported files, configuration and actual `score_before`, `score_after`, `improvement_percent`, evaluation status and timestamps. These are dataset-quality signals only.
2. **Independent model evaluation (optional, stronger):** same model architecture, compute budget, inference settings, prompt wrappers and test items for baseline and adapted training. Preserve immutable prediction JSONL with real outputs, numeric extraction method, and public hashes. No hand-edited outputs.

### Ablation plan

| Arm | Training dataset | Independent oracle QA |
|---|---|---|
| A (control) | Original 240-row seed | Standard format/schema validation |
| B (Adaption) | Adaption-enhanced version of seed | Standard format/schema validation |
| C (Adaption + oracle) | Adaption-enhanced data with invalid arithmetic and unsupported rates removed/corrected | Strict decimal oracle and clarification checks |

C must not be labeled as built unless it actually exists. If only arms A and B are available, report only that comparison. Match or record training tokens across arms because improvements from a larger dataset are not the same as improvements from verified correctness.

### Evaluation

1. Freeze train/dev/stress manifests and SHA-256 hashes **before** generating any model predictions. Gold cases and prompt pairs must not be reused as training rows.
2. Use `dev` for parser/format debugging and `stress` for the last public development evaluation; **do not claim these constitute an independent blind evaluation**, as both are generated by the same code families.
3. Commission or author a truly independent, human-checked blind set with new scenario templates, including varied phrasing, mixed accounting cycles, costs that exceed revenue, multi-line ledgers and realistic incomplete information. Keep its questions and answers away from training and model prompts until model selection is frozen.
4. Save exactly one prediction per case ID (or deliberately leave missing predictions to be counted wrong). JSONL schema: `{"id": "...", "kind": "numeric|clarify", "value": "string|null", "unit": "USD|units"}`. If a model outputs prose, publish an extraction protocol and retain both raw prose and parsed predictions. Do not manually overwrite bad predictions.
5. Report: accuracy, strict pair accuracy, numeric accuracy, clarification accuracy, per-family breakdown, before/after delta, scenario-paired bootstrap 95% CI, pair-level exact McNemar p-value, and error examples.
6. Never describe an Adaption native score of 9.4/10 as 94% correctness or as numerical model accuracy. Platform scoring and evaluation dataset are distinct.

### Error taxonomy to disclose

- Wrong arithmetic, rounding or units.
- Hallucinated FX rate, tax rule, exchange-rate date or fee.
- Incorrect deduction of duplicate receipts.
- Unjustified answer to inconsistent/negative inventory.
- Incorrect simple/compound distinction.
- Missed fee basis (per-item versus flat).
- Excessive refusal when adequate information is provided.
- Parsing/extraction failures counted as wrong.

### Protocol threats

- **Template leakage:** lexical split separation does not prove semantic novelty; shared family generator is a development convenience. Require independent blind templates for final empirical claims.
- **Independence:** two members of a counterfactual pair are correlated. Bootstrap by scenario ID and use strict-pair McNemar significance. Do not treat all row scores as statistically independent.
- **Synthetic simplicity:** current tasks are short and may overestimate field performance.
- **Unverified labels:** formulas have deterministic oracles and unit tests, but human financial-domain review is still missing.
- **Transfer uncertainty:** test any trained assistant on realistic new user prompts; improvement in dataset quality may not transfer to deployment.
- **Licensing:** original author-generated synthetic fixtures are CC0-labeled; confirm separate rights for Adaption-generated or customer-sourced content before redistributing.

### Independent verification gate

Before proclaiming a winning result, require:
- Adaption-exported original and improved files with hashes and visible dataset IDs.
- At least 30 blinded human-checked scenarios across all task families (preferably 120+).
- A genuine pre/post model or dataset-quality evaluation with immutable artifacts.
- At least two manually inspected failures and two successes for both variants; include limits and negative results.
- A runnable reproduction command from a fresh environment.

## Safe execution

The public repository contains a GitHub Actions secret reference, **not** the token. No workflow on pull-request events should access `ADAPTION_API_KEY`. The manual upload helper never adapts or trains, and the separate Invent launcher remains approval/credit gated.

Do not run any credit-consuming Adaption call unless its **actual current estimate**, balance and explicit owner-approved ceiling have been checked. A GitHub test passing is not a guarantee that an external provider request will be accepted.
